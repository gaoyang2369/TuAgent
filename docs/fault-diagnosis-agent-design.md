# G120 故障诊断 Agent 业务能力设计大纲

建议首版采用 **6 个只读工具 + 3 个业务 skill**。工具负责读数据、算指标、找事件和检索手册，返回可核对的结果。skill 负责编排这些工具，规定每类判断需要哪些证据，以及怎样向用户表达结论。简单查询可以直接调用一个工具，一次故障诊断也可以沿用同一份证据生成报告。

设计范围为 `dcma` 中采用 `g120_sim_v1` 字段定义的四张模拟遥测表。采样间隔为 3 秒，滚动保留 7 天。下文的诊断窗口是首版建议值，演示模型的物理量与阈值尚未经真实 G120 设备校准。现场保护设定需要独立的设备配置来源。

**当前进度为第一阶段已实现并通过复核，第二阶段接入故障码与手册。** 第 6 节收录模拟数据接入资料，第 7 节保留第一阶段任务，第 8 节是下一阶段可直接交给 Codex 的指令。第一阶段的调用示例与实测结果见[遥测接入与验收记录](telemetry-usage.md)。

## 1. 三个 skill 如何承接用户请求

| 业务入口 | 由谁负责 | 工作方式与产出 |
|---|---|---|
| “最近 10 分钟转速如何？”“昨天堵转了几次？” | `telemetry-analysis` 数据分析 skill | 按问题选择原始采样、窗口统计或事件计数。给出数据源、时间范围、单位、覆盖情况，并说明次数的口径。单纯查字段或最新值可直接调用对应工具。 |
| “F30002 是什么意思？” | Agent 直接调用 `lookup_drive_code` | 用完整代码查找对应条目。用户追问手册中的适用条件或可能原因时，再检索相关章节。只问代码含义时无需读取遥测。 |
| “这次为什么停机？”“没有报码，转速为什么下滑？” | `fault-diagnosis` 故障诊断 skill | 从故障事件或用户给出的异常时刻定位窗口，根据现象选择取证步骤。产出结构化诊断记录，区分观测事实、候选原因和待核实项。 |
| “把刚才那次故障整理成报告。” | `diagnostic-report` 诊断报告 skill | 读取已有诊断记录和证据引用，按模板生成 Markdown。若从报告请求开始且尚无记录，先执行诊断流程。 |

三类故障分别作为 `fault-diagnosis` 中的取证指引维护，共用事件提取、统计和检索工具。首版的报告交付物是 Markdown 文本。以后若要求生成 PDF 或存入指定系统，再为相应的渲染或存储动作增加工具。

## 2. 六个工具及其契约

下表中的“源”指一张白名单遥测表及其字段配置版本。“窗口”统一为样本时间的左闭右开区间 `[start, end)`。

| 工具 | 主要输入 | 返回结果与口径 |
|---|---|---|
| `get_signal_metadata` 字段定义 | 源、字段列表 | 在本仓库实现字典读取，按 `schema_name + table_name + profile_version + field_name` 取定义。返回单位、换算、枚举、符号、无效值、`verification_status`、适用范围和模型校验值 `source_sha256`。 |
| `query_telemetry` 原始采样 | 源、字段、`latest` 或历史窗口、条数或游标 | 在本仓库实现两种模式。`latest` 选取最近最多 1000 点，约 50 分钟。历史模式按起止时间查询和分页。两者均按样本时间升序返回原始点、字段定义、`values_are`、覆盖情况及截断信息。 |
| `summarize_telemetry` 窗口统计 | 源、窗口、字段、分桶粒度、所需指标，可选带单位和来源的阈值 | 在数据侧计算每桶有效点数、极值及其时刻、均值、变化率或连续超限时长。阈值比较使用同一单位，持续时长按连续有效采样段给出，遇缺口断开。适合数小时趋势和较长窗口统计。 |
| `find_code_events` 报警与故障事件 | 源、窗口、`fault_code` 或 `alarm_code`、可选目标码 | 返回与窗口相交的事件、触发和清除的观测时刻、跨窗或缺口标记，以及窗口内可确认的新触发次数。保留事件引用，供诊断回查前后原始点。 |
| `lookup_drive_code` 代码精确查询 | 完整故障码或报警码、设备系列、可用的手册版本或固件信息 | 从代码索引精确匹配，保留 `F`/`A` 前缀及前导零。命中时返回代码类型、条目释义、适用版本和手册引用。无条目或版本有歧义时返回对应状态。 |
| `search_manual` 手册检索 | 现象或问题、设备系列，可选代码、手册版本和章节范围 | 在适用文档中检索相关段落，返回原文片段、手册标识、版本、页码或章节锚点。供诊断 skill 查找手册列出的原因、判别条件及核查项。 |

**遥测适配约定**

- 数据源白名单为 `sim_normal`、`sim_f07900_blocked`、`sim_f30002_overvoltage`、`sim_f07011_overtemp`。四表的设备名同为 `G120_SIM`。用户只给设备名时，按表分别查询和列示结果。后三张表都含运行、故障及恢复阶段，表名和预设根因仅用于选源与评测。
- 将 `timestamp` 的 Unix 毫秒字符串按数值解释，对外展示北京时间。`id` 是行主键，可辅助稳定排序。窗口查询记录读取时刻、请求与实际范围、期望点数、实有点数、各字段有效点数及缺口。分页截断需明示。历史可补入，`create_time` 也是样本时刻，无法据此推算入库延迟。
- 原始查询保留存储值并标记无效点，统计时先剔除无效值，再按字段字典换算并注明所用单位。`air_intake_temp` 的 `-200` 和 `NULL` 计入无效点数，零转速、零电流和代码字符串 `'0'` 都有业务含义。运行状态采用 `RUNNING`、`STOPPED`、`FAULT`。字典保留 `actual_solution` 的定义，遥测和诊断输入排除该列。`simulation_assumption` 标记模型约定，`verified_simulator` 标记已与模拟程序核对的定义。
- 后端使用只读连接、表和字段白名单、绑定查询参数，并限制窗口、字段数、单页点数及统计桶数。分别返回版本校验失败、读取失败、窗口无覆盖等状态。超出保留期的部分标为不可用。

**事件计数约定**

故障码和报警码各自识别状态转换。查询时多取窗口开始前的一个样本。同一源中，按 3 秒采样周期连续的两个有效样本从 `'0'` 变为目标码，且变化落在窗口内，才计一次新触发。之后的同码行属于同一次锁存。由该码回到 `'0'` 的首个连续采样点记为清除，不同非零码直接切换时单列代码变化。温度或电压回落后，仍以代码转换判断锁存是否解除。

窗口首点已带码且前一点同码，列为跨窗延续。若缺少相邻前样本、内部采样中断或窗口结束时仍带码，标明相应边界未知，只报告可确认的次数和时段。例如连续读到 `'0' → F07900 → F07900 → '0'`，结果为一次触发、一次清除。

**故障码与 RAG 的分工**

手册入库时按设备系列、版本、代码和章节建立索引。代码索引和段落检索共享同一套文档引用。问代码含义优先精确匹配，问“哪些原因符合此次现象”再按适用范围做关键词及语义检索，并逐项对照遥测。第 6 节收录了模拟场景说明，手册原文、适用版本和页码仍待接入。没有适用条目时，将手册释义标为待核实。若该码已有模拟含义，可引用第 6 节并注明适用范围。

## 3. 诊断 skill 的取证指引

以首次观测到代码触发的样本时刻为 `T`。无报码时以用户指定时刻或统计定位的异常时段取证，分别记录信号异常与报码状态。起点不明时记录首个可见时刻及缺失历史。

| 场景 | 建议取证窗口与字段 | 支持的判断和待核实项 |
|---|---|---|
| 堵转 `F07900` | 先看 `T` 前 60 秒至后 30 秒的 3 秒原始点。对齐 `speed_setpoint`、`speed_actual`、`torque_actual`、`current_actual` 和 `fault_code`。 | 指令仍在、实际转速趋零、转矩持续处于高位，随后报码并撤除电流和转矩，支持堵转现象。演示模型的转矩平台约 3.5 N·m、持续约 15 秒，报告采用窗口内的采样值和可见时长。机械卡滞可列为优先假设，仍需核对转矩限值、编码器反馈及机构状态。 |
| 母线过电压 `F30002` | 先看 `T` 前后各 30 秒的原始点。对齐 `speed_setpoint`、`speed_actual`、`torque_actual`、`actual_power`、`feedback_power`、`dc_voltage` 和故障码。 | 核对减速、负转矩、负轴功率与母线升压的先后关系。模拟母线约 9 秒从 557 V 升至演示阈值 800 V，报告保留窗口内的采样峰值及其时刻。`feedback_power` 是由轴功率派生的非负幅值，两者属于同一条功率证据。可优先怀疑减速回馈，供电电压和制动电阻状态仍待核实。跳闸后转子可继续滑行。 |
| 电机超温 `F07011` | 先取 `T` 前 3 小时至后 30 分钟的 1 分钟趋势，必要时扩至 6 小时。对齐 `current_actual`、`motor_load_rate`、`torque_actual`、`motor_temp`、`air_intake_temp`。分别定位 `A07910` 报警和 `F07011` 故障，再读取两处附近原始点。 | 核对持续过载、温升、报警、跳闸和冷却的时序。`motor_load_rate` 是电流负载率。演示中约 130 °C 报警、145 °C 跳闸，触发约在本轮第 1 小时 48 分钟。停机后的零电流仍需结合触发前历史解释。若历史覆盖不足，保留超温观测，将持续过载原因列为待核实。 |
| 正常对照或证据不足 | 在请求窗口内检查代码、转速跟踪、电流、电压、温度及有效覆盖率。`sim_normal` 只提供空载或轻载的对照。 | 覆盖充分且信号平稳时，可答“该窗口未见上述异常”。若有明显异常却无报码，报告信号和异常时段。若有缺口，标出无法判断的时段。 |

## 4. 从诊断记录到报告

以“最近一次电机超温为什么停机，出一份报告”为例，三个阶段复用同一个事件和同一组证据。

1. **定位事件。** 在选定数据源的可用历史内用 `find_code_events` 定位最近的 `F07011` 触发，记录事件引用和 `T`。若只看到跨窗锁存，先向前扩窗寻找触发点。保留期内仍找不到时，标明起点未知。
2. **建立时间线。** `summarize_telemetry` 取长窗口的电流负载率与温升趋势。用 `find_code_events` 查找同一源、本次运行中 `T` 之前的 `A07910`，用 `query_telemetry` 回读报警和跳闸附近的原始点。用 `lookup_drive_code` 核对代码释义，必要时用 `search_manual` 补充判别条件。记录与过载温升假设相符、相悖或缺失的证据。
3. **形成记录并出报告。** `fault-diagnosis` 按下表生成诊断记录，`diagnostic-report` 以此输出摘要、事件时间线、证据、可能原因和待核实项。若缺少触发前数据或适用手册，仍可就已观测事实出具有限结论。

| 诊断记录内容 | 报告如何使用 |
|---|---|
| 数据源、字段版本、查询时刻、请求与实际覆盖范围、缺口 | 说明本次判断适用的对象、时段，以及历史补入或保留期带来的限制。 |
| 事件引用、报警与故障代码、触发和清除时刻或边界状态 | 生成时间线，区分故障前发展、跳闸、锁存和恢复。 |
| 遥测工具返回的证据引用及带单位的值。原始点引用含源、字段、时刻和行主键，统计桶引用含源、字段、窗口、指标和计算参数 | 将每个关键数值关联到原始点或统计桶。保存实际使用的证据值，以便滚动数据过期后仍可核对报告。 |
| 手册引用、适用版本、支持及相悖证据、候选原因、缺失配置或现场核查项 | 分开表述“观测到什么”“优先怀疑什么”“还需要确认什么”。报告中的数字和引文均取自诊断记录。 |

## 5. 接入顺序与验收

| 顺序 | 交付范围 | 可复核的验收例子 |
|---|---|---|
| ① 遥测与事件 | 从零实现 MySQL 读取、字段字典、最新与历史采样、窗口统计、事件提取，并将四个工具与 `telemetry-analysis` 接入 Agent。 | 能查询 3 小时超温历史，区分无效进气温度与有效零值。同一码锁存多行只计一次，窗口从锁存中途开始时新触发计零且列为延续。缺前样本时将起点标为未知。 |
| ② 代码与手册 | 接入可溯源的 G120 手册，建立代码索引和段落检索。 | 精确区分 `A07910` 和 `F07011`，命中条目可回到对应版本与章节。对未知代码或不适用版本返回明确状态。 |
| ③ 诊断与报告 | 接入三类取证指引、诊断记录和 Markdown 报告模板。 | 堵转引用触发前转速与转矩，过压引用原始电压峰值，超温引用过载至报警、跳闸的时间线。正常窗口不误报，缺证时说明结论边界。报告中的数值、窗口和引用能逐项追溯到诊断记录。 |

评测时可用模拟场景的预设根因核对结果。给诊断 skill 的评测输入使用不含场景含义的数据源别名，并覆盖同一故障表中的正常段、触发段和恢复段，以检验结论是否确实来自观测证据。

业务工具仅读取下节四张遥测表及字段字典 `dcma.signal_metadata`。每表每 3 秒写入一条，一周完整数据约为每表 201,600 条。四表沿用旧表的 32 列及存储类型，旧表 `real_data` 和 `real_data_01` 至 `real_data_04` 保持原有定义，位于本次接入范围之外。

数据生成服务 `dcma-g120-simulator.service` 部署在 `10.108.13.250` 的 `/home/lenovo/dcma-g120-simulator`。它负责断线重连、按历史时刻补齐及清理超过 7 天的数据。工具读取的是查询时已经存在的样本，同一历史窗口在补齐后可能得到更多点。模拟场景按样本时间确定性生成，适合回归测试，现场故障发生概率需要独立数据估计。

### 6.2 四张遥测表与场景参数

| 白名单表 | 周期与演示设定 | 演化顺序与验收参照 |
|---|---|---|
| `sim_normal` | 空载或轻负载对照。转速约 1000 rpm，母线约 557 V，电流约 1.06 A，电机约 42 °C。 | 转速小幅周期波动、跟踪正常。`fault_code` 与 `alarm_code` 均为字符串 `'0'`。 |
| `sim_f07900_blocked` | 30 分钟一轮，预设机械卡滞。指令约 1000 rpm，触发前电流约 2.31 A、电机电流负载率约 126%。 | 实际转速趋零、转矩升高，零速下约 3.5 N·m 持续 15 秒，随后出现 `F07900`。电流及电磁转矩撤除，经历锁存、模拟排障、复位和重新启动。 |
| `sim_f30002_overvoltage` | 30 分钟一轮，预设快速减速时回馈能量未充分消耗。高惯量运行时升至约 1400 rpm。 | 减速出现负转矩和负轴功率，母线约 9 秒内从 557 V 升至演示阈值 800 V，随后出现 `F30002`。电流及电磁转矩撤除，转子滑行、母线回落，再复位重启。 |
| `sim_f07011_overtemp` | 6 小时一轮，预设持续过载引起热积累。环境约 25 °C，过载时电流约 2.18 A、电机电流负载率约 119%、转矩约 3.25 N·m。 | 电机逐渐升温，约 130 °C 出现 `A07910`，本轮约第 6480 秒（1 小时 48 分钟）达 145 °C 并触发 `F07011`。电流和转矩撤除，冷却时故障仍可锁存，随后复位重启。 |

这些周期和参考数值用于设计测试样本。查询某段时间内的峰值、事件次数或持续时长时，从该窗口的实际采样计算。实际保护阈值、转矩限制、铭牌参数和传感器映射需有各自的配置来源。

| `status` | `VARCHAR(50)` | 状态枚举 | `RUNNING`、`STOPPED`、`FAULT`。按字符串解释。 |
| `fault_code` | `VARCHAR(50)` | 故障码字符串 | `'0'` 表示无故障，非零码可锁存多行。 |
| `alarm_code` | `VARCHAR(50)` | 报警码字符串 | `'0'` 表示无报警，超温场景使用 `A07910`。 |
| `control_word` | `VARCHAR(50)` | 十进制字符串 | 模拟运行与停止指令使用 `5247`、`5246`。 |
| `status_word` | `VARCHAR(50)` | 十进制字符串 | 简化状态字，现场 PLC 位映射尚待核实。 |
| `dc_voltage` | `FLOAT` | V | 直流母线电压。 |
| `speed_setpoint` | `FLOAT` | rpm | 指令转速。 |
| `speed_actual` | `FLOAT` | rpm | 实际转速。 |
| `current_actual` | `FLOAT` | A | 电流幅值。 |
| `torque_setpoint` | `FLOAT` | N·m | 指令转矩。 |
| `torque_actual` | `FLOAT` | N·m | 实际电磁转矩。模型中负值表示制动转矩。 |
| `air_intake_temp` | `FLOAT` | °C | 模拟进气环境温度。`-200` 与 `NULL` 均为无效值。 |
| `motor_temp` | `FLOAT` | °C | 电机温度。 |
| `inverter_temp` | `FLOAT` | °C | 变频器温度。 |
| `actual_power` | `FLOAT` | kW | 有符号轴输出功率。负值表示再生运行，电网输入功率需要单独测量。 |
| `field_current` | `FLOAT` | A | 励磁电流分量。 |
| `torque_current` | `FLOAT` | A | 有符号转矩电流分量。 |
| `system_run_time` | `VARCHAR(50)` | 秒数字符串 | 模拟累计秒计数，跨场景轮次累计。 |
| `inverter_radiator_temp` | `FLOAT` | °C | 变频器散热器温度。 |
| `inverter_load_rate` | `FLOAT` | % | 电流相对模拟变频器额定电流的比例。 |
| `motor_load_rate` | `FLOAT` | % | 电流相对模拟电机额定电流的比例，描述电流负载。 |
| `pulse_frequency` | `FLOAT` | kHz | 演示配置固定为 4 kHz。 |
| `motor_power` | `FLOAT` | kW | 模拟参考额定功率，固定为 0.46 kW。瞬时轴输出功率见 `actual_power`。 |
| `feedback_power` | `FLOAT` | kW | 回馈功率的非负幅值，由 `actual_power` 派生。 |
| `create_time` | `DATETIME` | 北京时间 | 在此模型中保存样本时刻，历史补入时也使用历史时刻。 |
| `actual_solution` | `TEXT` | `NULL` | 保留列，模拟数据始终为空，仅保留字段定义。 |

模型使用以下关系生成数据，可据此解释单位和派生关系。工具读取数据库中实际保存的采样值。

```text
current_actual     = sqrt(field_current² + torque_current²)
torque_current     = torque_actual / 1.7
actual_power       = torque_actual × speed_actual / 9549.296586
feedback_power     = max(0, -actual_power)
motor_load_rate    = current_actual / 1.83 × 100
inverter_load_rate = current_actual / 2.30 × 100
```

其中 1.7 N·m/A 是模拟转矩换算系数，1.83 A 和 2.30 A 分别是电机、变频器的模拟参考额定电流。

### 6.4 `signal_metadata` 字段字典与版本

资料记录 `g120_sim_v1` 共有 128 条定义，即 4 张表各 32 条。按 `schema_name`、`table_name`、`profile_version`、`field_name` 四项精确匹配。例如 `dcma / sim_f07011_overtemp / g120_sim_v1 / motor_temp` 指定了超温表中电机温度的定义。运行时以查到的字典为准。

| 字典字段 | 用法 |
|---|---|
| `description`、`quantity_kind` | 展示字段含义和物理量类别。 |
| `storage_type`、`is_nullable` | 解释存储类型和可空性。 |
| `stored_unit`、`display_unit`、`canonical_unit` | 分别对应存储、展示和分析使用的单位。 |
| `scale_factor`、`offset_value` | 提供换算倍率和偏移。统计须说明所用单位，只换算一次。 |
| `value_conventions` | JSON，保存正负方向、枚举、公式和参考量等语义。 |
| `invalid_values` | JSON，保存逐字段无效值规则。 |
| `definition_source`、`scope_note` | 定义来源及适用范围，随证据返回。 |
| `verification_status` | `simulation_assumption` 表示单位、语义或参数属于模拟假设。`verified_simulator` 表示已核对模拟程序的格式或行为。两种状态的适用范围均为模拟器。 |
| `source_sha256` | 对应模拟器模型文件的版本校验值。随定义返回，并检查同一源及版本的定义是否一致。 |

资料没有提供可独立核验的预期 SHA-256。若部署配置提供了可信预期值，工具须比对，冲突时返回版本错误。没有预期值时，保留字典返回的哈希并注明“已检查字典内部一致性，未独立核验模型文件”。缺少所请求的字段定义时，指出具体字段与版本。
